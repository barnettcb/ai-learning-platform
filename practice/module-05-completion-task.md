# Module 5 Completion Task — Repair Without Restarting

## Starting exchange
### User request
“Create a short guide that helps new volunteers greet visitors at our community center.”

### AI response summary
The response contains a useful five-step sequence but is two pages long, uses formal customer-service language, assumes volunteers can answer every question, and does not explain what to do when they do not know an answer.

## Instructions
Write a follow-up request that:
1. preserves the useful sequence;
2. diagnoses the specific weaknesses;
3. clarifies the intended audience and tone;
4. adds the missing uncertainty or escalation instruction;
5. requests a focused revision rather than a complete restart; and
6. decides whether a short example would clarify the desired wording pattern or would overconstrain the result.

When an example would help, include one brief pattern. When it would not, explain why the instructions are already clear enough.

## Evaluation criteria
A successful repair:
- states what should remain;
- identifies concrete failures rather than saying “make it better”;
- corrects the missing requirements;
- uses an example only when it adds a useful pattern;
- avoids repeating the full original assignment;
- does not request changes unrelated to the diagnosed problems.
